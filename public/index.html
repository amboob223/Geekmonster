How it works

The evidence chain.

Whether run by hand today or by tooling later, every engagement walks the same six stages end to end. Nothing reaches a client deliverable if it skips a link.

01

Recon

Map the repo — contracts, dependencies, inheritance, access control, upgradeability.

02

Hunt

Static analysis + AST + LLM reasoning flag candidates. The model is never the sole source of truth.

03

Exploit

A Foundry PoC executed against an isolated Anvil fork. Detection ≠ confirmation.

04

Verify

Adversarial review classifies each candidate — and preserves the evidence either way.

05

Score

Exploitability, funds at risk, and blast radius — scored and explained, not asserted.

06

Remediate

A patch, shown as a diff, retested against the original exploit and the full test suite.

Every finding is classified: VERIFIED LIKELY SUSPECTED FALSE POSITIVE — never asserted on model output alone.

What we won't oversell

What's genuinely hard.

A firm that only tells you what's easy isn't one worth trusting with your contracts.

  • —

    Exploit generation for novel vulnerability classes reliably — fuzzing and invariant testing are expensive and can still miss logic bugs.

  • —

    Keeping the model from hallucinating findings or exploit correctness — this is why static analysis and reproducible tests are load-bearing, not optional.

  • —

    A patch that compiles is not a patch that's correct — verification needs the original exploit to demonstrably fail, and the full regression suite to stay green.

  • —

    Maintaining a real provenance chain from finding to report is more overhead than it sounds — and it's the difference between a credible report and a plausible-looking one.

  • —

    PQC migration guidance requires real protocol-compatibility and performance modeling, not just algorithm swaps — the slowest capability to build well.
